# قرارات التصميم والتعديلات على الوثيقة الأصلية

هذه الوثيقة تسجل ما أُضيف أو حُذف أو عُدّل على وثيقة المواصفات الأصلية (الإصدار 1.0) ومبرر كل قرار.
المواصفات الأصلية تبقى المرجع لكل ما لم يُذكر هنا.

## ما أُضيف

| # | الإضافة | المبرر |
|---|---------|--------|
| A1 | **واجهة سطر أوامر `x2p`** (`inspect` / `convert` / `engines`) | المواصفات تشترط تشغيل الفحص والاختبارات دون واجهة رسومية؛ CLI يحقق ذلك ويفيد في الأتمتة والدفعات. |
| A2 | **محرك Microsoft Excel اختياري (COM)** بجانب LibreOffice | عند وجود Excel على الجهاز يعطي أعلى تطابق ممكن مع المصدر. **ليس شرطًا**: المحرك الافتراضي يبقى LibreOffice، والمسار الأساسي يبقى مجانيًا. يُستخدم أيضًا كمرجع للمقارنة (بند 12.3). |
| A3 | **عامل تحويل منفصل في عملية مستقلة (out-of-process worker)** | تشغيل كل تحويل في عملية منفصلة بمهلة زمنية وملف تعريف مؤقت يمنع تعليق الواجهة، ويعزل أعطال المحرك، ويسمح بتحويلين متزامنين (بند 12.2). |
| A4 | **المحرك نفسه يُصدِّر "النص المعروض" لكل خلية** | تنسيق الأرقام والتواريخ في Excel معقد؛ بدل محاكاته نأخذ النص كما يعرضه المحرك (`Range.Text` / `getString()`) ونقارنه بنص PDF. هذا يجعل فحص التغطية النصية دقيقًا ومستقلًا عن المحرك. |
| A5 | **قياس أصغر خط فعليًا من PDF** | بدل حساب الحجم نظريًا من المقياس، نقرأ أحجام الخطوط الفعلية من PDF عبر PyMuPDF. التقرير يعرض رقمًا مقاسًا، لا تقديرًا. |
| A6 | **تقرير JSON آلي** بجانب التقرير المرئي | يسهل اختبارات الانحدار والتكامل مع أنظمة أخرى. |
| A7 | **فهرس (Bookmarks) لكل ورقة داخل PDF** | يسهّل التنقل في الملفات متعددة الأوراق. (خيار PDF/A مؤجَّل: دمج الأوراق المصدَّرة منفصلة لا يضمن مطابقة PDF/A، وسيُضاف بعد تنفيذ تصدير بمرور واحد.) |
| A8 | **سياسة "اختبار قبل إعلان الدعم" مُرمَّزة** | جدول صيغ داخل الكود (`SUPPORTED_FORMATS`) بحالة `supported / experimental / unsupported`؛ XLSB مرفوض حتى يجتاز الاختبارات. |

## ما حُذف أو استُبدل

| # | المحذوف | البديل والمبرر |
|---|---------|----------------|
| R1 | **Pillow** | PyMuPDF يرسم صفحات PDF إلى صور مباشرة، وQt يعرضها. مكتبة أقل = اعتماديات وتراخيص أقل. |
| R2 | **QtPdf** للمعاينة | موجود فقط في حزمة PySide6-Addons الكبيرة. نرسم الصفحات عبر PyMuPDF (نفس الملف النهائي فعليًا) ونستخدم PySide6-Essentials فقط. |
| R3 | **الاعتماد على UNO من Python الخاص بالتطبيق** | على Windows لا يمكن استيراد `uno` من Python عادي. العامل يُشغَّل بـ Python المرفق مع LibreOffice نفسه ويتواصل عبر ملف JSON. |
| R4 | **تشغيل openpyxl على ملفات XLS** | openpyxl لا يقرأ XLS؛ نستخدم `xlrd` للقراءة فقط. |

## ما عُدِّل

| # | التعديل | المبرر |
|---|---------|--------|
| M1 | Python **3.12** مؤكد، وPySide6 **6.12**، وPyMuPDF (اسم الاستيراد `pymupdf` بدل `fitz` المهمل). | أحدث إصدارات مستقرة. |
| M2 | **ترخيص المشروع: GPL-3.0** | PyMuPDF مرخص AGPL-3.0؛ بما أن المشروع مفتوح المصدر ومجاني فهذا متوافق، ويجب ذكره صراحة. AGPL يغطي الاستخدام عبر الشبكة ولا يؤثر على تطبيق سطح مكتب محلي يُوزَّع مع مصدره. |
| M3 | الحد الأدنى للخط يُقاس على **أصغر خط بيانات** وليس على الحواشي | الرؤوس والتذييلات قد تكون صغيرة عمدًا (ترقيم صفحات) ولا تعني نصًا غير مقروء. |
| M4 | "تجربة خطة بديلة واحدة فقط" تُطبَّق: إذا فشل التحقق في الوضع التلقائي نجرب ملاءمة العرض مع التقسيم، ثم نتوقف. | مطابق لبند 6 المرحلة 7. |

## الحالة الحالية للتنفيذ

- [x] نماذج البيانات، الفاحص (XLSX/XLSM/XLS)، محرك التخطيط، محولا المحرك، التحقق، التقرير.
- [x] CLI + واجهة PySide6 (عربي/إنجليزي، RTL، معاينة PDF الفعلي، تقرير التحقق).
- [x] ملفات اختبار اصطناعية + 55 اختبار pytest ناجحة على المحركين (LibreOffice و Excel).
- [x] إثبات الصلاحية على LibreOffice 26.8 — **بوابة القرار في §14 اجتيزت على الملفات الاصطناعية**.
- [x] اختبار على ملف حقيقي (60 عمودًا، عربي، نصوص طويلة) — يجتاز على المحركين بعد إصلاحات المرحلة الثانية.
- [x] وضع "بطاقة لكل سجل" (اختياري، يُقترح عند 4 أجزاء أفقية أو أكثر)، وتحسين تقدير الصفحات بعد اللف.
- [x] تحكم يدوي بالهوامش وفواصل الصفحات (كل N صف) وخطوط الشبكة وتوسيع الأعمدة من نافذة الإعدادات اليدوية.
- [ ] مقارنة انحدار بصرية بصور مرجعية.
- [x] حزمة Windows محمولة (zip، 52 MB) تعمل دون Python. مثبّت MSI/توقيع رقمي: لاحقًا.

## قرارات إضافية من إثبات الصلاحية

|---|---------|--------|
| M5 | التخزين المؤقت في مجلد `x2p-jobs` داخل `%TEMP%` بدل `%LOCALAPPDATA%` | Excel رفض الكتابة داخل مجلدات `%LOCALAPPDATA%` على جهاز الاختبار. مجلد `%TEMP%` خاص بالمستخدم أيضًا. |
| M6 | كل ورقة تُصدَّر منفصلة ثم تُدمج مع فهرس | ربط دقيق بين الصفحات والأوراق للتحقق والمعاينة، وإمكانية إعادة محاولة ورقة واحدة. الثمن: ترقيم الصفحات يبدأ من 1 في كل ورقة. |

## قرارات المرحلة الثانية (بعد اختبار الملف الحقيقي — انظر [REAL_FILE_TEST.md](REAL_FILE_TEST.md))

| # | القرار | المبرر |
|---|---------|--------|
| P1 | **لفّ النص الذي سيُقص** تلقائيًا في نسخة العمل (يمكن إيقافه `wrap_overflow=False`) | الملف الحقيقي فيه ~1000 خلية مقصوصة حتى في Excel. الوثيقة تمنع القص غير المعلن؛ اللف يحفظ البيانات ويُعلَن في التقرير. |
| P2 | **ملحق النصوص الطويلة** (افتراضي؛ بديله: لفّ داخل الخلية) | لفّ نص من آلاف الحروف داخل خلية ينتج مئات الصفحات الفارغة، ويصطدم بحد ارتفاع الصف في Excel (409 pt). الملحق يحفظ النص كاملًا وقابلًا للبحث، والخلية تحمل رقم الإحالة. |
| P3 | الملحق **يرسمه المحرك** كورقة إضافية في نسخة العمل، لا PyMuPDF | طبقة نص PyMuPDF للعربية أخرجت محارف خاطئة، أي نصًا غير قابل للبحث. |
| P4 | **الخطة البديلة تعتمد المقياس المقاس** لا النظري | Excel يرسم الخطوط أصغر بنحو 9% من المقياس المطلوب. |
| P5 | **فئة "ترتيب عربي غير مُثبت" = تحذير** | طبقة نص PDF في المحركين تبعثر ترتيب بعض الحروف العربية مع أن العرض سليم. إن وُجدت كل الحروف في الصفحة يُطلب فحص بصري بعناوين الخلايا، وإلا فهو خطأ. |
| P6 | تقدير الصفحات لكل ورقة في الواجهة + نافذة إعدادات يدوية لكل ورقة | من متطلبات المرحلة الثانية في الوثيقة (§5.4، §14). |

## قرارات الإصدار 0.3.0

| # | القرار | المبرر |
|---|---------|--------|
| D1 | **حزمة محمولة (zip) عبر PyInstaller** بدل مثبّت | تعمل بفك الضغط على أي جهاز Windows 10/11 دون صلاحيات مدير. المثبّت والتوقيع الرقمي يأتيان بعد استقرار الإصدار. |
| D2 | **LibreOffice لا يُضمَّن في الحزمة** | حجمه نحو 350 MB وله شروط توزيع خاصة. التطبيق يكتشف غيابه ويعرض تثبيته عبر winget (بنقرة من المستخدم) أو يفتح صفحة التحميل الرسمية. |
| D3 | **وضع البطاقات لا يُطبَّق تلقائيًا** | الوثيقة §7.4 تمنع إعادة ترتيب البيانات آليًا. يُقترح ويُقدَّر عدد صفحاته، والقرار للمستخدم. على الملف الحقيقي أنتج صفحات أكثر من وضع الجدول (340 مقابل 260) لأن معظمه نصوص طويلة، لذلك لا يُعرض على أنه يقلل الصفحات. |
| D4 | حذف مكونات غير مستخدمة من الحزمة (numpy، نماذج ONNX، OpenGL البرمجي) | خفض الحجم من 110 إلى 52 MB، مع اختبار الحزمة بعد الحذف على المحركين. |

## قرارات الإصدار 0.4.0 (ملف مُصدَّر من نظام: 580 صفًا × 25 عمودًا بعرض افتراضي)

| # | القرار | المبرر |
|---|---------|--------|
| W1 | **توسيع الأعمدة الضيقة في نسخة العمل** (تلقائي/يدوي فقط، قابل للإيقاف) | الملفات المصدَّرة من الأنظمة تترك كل الأعمدة بالعرض الافتراضي. النتيجة كانت لفًّا في أعمدة ضيقة، و4312 خلية في الملحق (291 صفحة)، و`###` في التواريخ، وتجاوز مهلة Excel. بعد التوسيع: 60 صفحة على LibreOffice و84 على Excel، بلا ملحق ولا `###`. |
| W2 | **أعمدة الأرقام والتواريخ تأخذ العرض الذي تحتاجه دائمًا** (عدا الإبقاء على الأصل) | `###` فقد بيانات. العرض يُحسب من تنسيق الرقم أو التاريخ. |
| W3 | **المخطط يجرب عدة سقوف لعرض أعمدة النص ويختار الأقل صفحات** (مع صفحات الملحق) | لا يوجد عرض واحد مناسب لكل الملفات: أحيانًا يكون اللف أوفر، وأحيانًا السطر الواحد. |
| W4 | **الكلمات الطويلة (روابط، رموز) تُلف داخل الخلية ولا تُنقل للملحق** | ثبت بالتجربة أن المحركين يكسران الكلمة الأطول من العمود عند الحروف دون فقد. الملحق للنصوص الطويلة فعلًا فقط. وصف العمود لا يُنقل للملحق أبدًا. |
| W5 | **تقدير عرض النص حسب نوع الحرف، معايَر على PDF المحركين** | المعايرة أظهرت أن العربية أعرض بنحو 35% من التقدير السابق (Tahoma في LibreOffice، Arial في Excel). مع هامش 8%، ولفّ كل أعمدة النص كشبكة أمان، فأي خطأ في التقدير ينتج سطرًا ثانيًا لا قصًّا. |
| W6 | **خطوط الشبكة تُطبع للجداول بلا حدود** | جدول عريض بلا حدود يصعب تتبع صفوفه. قابل للإيقاف من الإعدادات اليدوية. |
| W7 | **Excel: تبديل طابعة نسخة Excel الخاصة عند رفض الطابعة الافتراضية لمقاس الورق** | طابعة شبكة غير متاحة جعلت Excel يصدّر Letter بدل A4. يُجرَّب بعدها Adobe PDF ثم بقية طابعات PDF، ويُذكر في التقرير إن لم ينجح أي منها. طابعة Windows الافتراضية لا تتغير. |
| W8 | **مهلة المحرك تزيد مع حجم الملف** (+1 ث لكل 50 خلية) | الأوراق الكبيرة تحتاج وقتًا أطول للّف وضبط ارتفاع الصفوف وجمع النصوص. |
| T1 | **قسم «القالب» في الصفحة الرئيسية، يبدأ باقتراح البرنامج** | القرار يصبح قرار المستخدم ويعرف شكل الملف قبل التحويل. البرنامج يقترح ولا يفرض، وما يغيّره المستخدم فقط يُحفظ. |
| T2 | **أولوية الصفوف/الأعمدة الثابتة:** اختيار المستخدم ← عناوين الطباعة في الملف ← الأجزاء المجمّدة ← الاكتشاف | التجميد تصريح من صاحب الملف بما يجب أن يبقى ظاهرًا. التجميد بعد الصف 10 أو العمود 5 يُعدّ اختيار عرض لا عناوين. |
| T3 | **«عرضًا ثم لأسفل» افتراضيًا عند التقسيم** | الافتراضي في المحركين يطبع كل صفوف الجزء الأول ثم الثاني، فيتباعد أجزاء السجل الواحد عشرات الصفحات. |
| T4 | **أرقام الصفوف عند غياب عمود ثابت** | تربط أي خلية في أي جزء بصفها دون تعديل البيانات. |
